# ระบบล็อกอินด้วยใบหน้า + ชื่อ + รหัสตัวเลข (Django + face-api.js)

โปรเจ็คนี้ให้ผู้ใช้สมัครสมาชิกด้วย **ชื่อ + รหัสตัวเลข (PIN) + ภาพใบหน้า** แล้วล็อกอินโดยต้องผ่านครบทั้งสามอย่าง
ทุกอย่างฟรี 100% และรันบนเครื่องตัวเอง (localhost) ไม่ต้องผูกบัตรเครดิต

- ตรวจจับ/จดจำใบหน้าด้วย **face-api.js** ในเบราว์เซอร์ (ไม่ใช้ face_recognition / dlib / OpenCV)
- เก็บข้อมูลด้วย Django 5 + SQLite, หน้าตาด้วย Bootstrap 5 (ภาษาไทย)
- ทุกครั้งที่ล็อกอินสำเร็จ จะบันทึกลง **Google Sheet** (ชื่อ-นามสกุล, ชื่อเล่น, รหัสสมาชิก, เวลา — ไม่มี PIN)
- ไฟล์ทุกอย่างที่ต้องใช้ (face-api.js, โมเดล, Bootstrap, ฟอนต์ Sarabun) **อยู่ในโปรเจ็คแล้ว** ใช้งานได้แม้ไม่มีอินเทอร์เน็ต (ยกเว้นตอนส่งขึ้น Google Sheet)

> สถานะ: ระบบหลักครบแล้ว ส่วน **ฟีเจอร์เสริม (ตรวจว่าเป็นคนจริง / หน้าสรุปรายงาน) ยังไม่ได้ทำ** — ตั้งใจให้ทำหลังจากระบบหลักทดสอบผ่านบนเครื่องของคุณแล้ว

## 2. ติดตั้งและรัน (Windows)

ต้องมี **Python 3.10 ขึ้นไป** (ตรวจด้วย `py --version`) — ถ้ายังไม่มี ดาวน์โหลดฟรีที่ python.org
ตอนติดตั้งให้ติ๊ก "Add python.exe to PATH"

เปิด **Command Prompt (cmd)** แล้วพิมพ์ทีละบรรทัด:

```bat
cd C:\path\to\face_login_project

py -m venv venv
venv\Scripts\activate.bat

pip install -r requirements.txt

py manage.py migrate
py manage.py runserver
```

จากนั้นเปิดเบราว์เซอร์ที่ **http://localhost:8000** (ต้องใช้ `localhost` หรือ `127.0.0.1` เท่านั้น
เพราะเบราว์เซอร์อนุญาตให้เปิดกล้องได้เฉพาะ localhost หรือ HTTPS)

ครั้งแรกที่เปิดหน้าสมัคร/ล็อกอิน เบราว์เซอร์จะถามสิทธิ์ใช้กล้อง ให้กด "อนุญาต"

หมายเหตุ:
- ถ้าใช้ PowerShell แล้วขึ้นว่าสั่ง `Activate.ps1` ไม่ได้ ให้ใช้ cmd ตามข้างบน
  หรือรัน `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` หนึ่งครั้ง
- ครั้งถัดไปที่เปิดเครื่องใหม่ ทำแค่ `cd` → `venv\Scripts\activate.bat` → `py manage.py runserver`

### สร้างบัญชีผู้ดูแล (ไม่บังคับ แต่แนะนำ)

```bat
py manage.py createsuperuser
```

แล้วเข้า http://localhost:8000/admin/ เพื่อดูสมาชิก ประวัติการล็อกอิน สถานะการส่งชีต
และ **ลบสมาชิก** ได้ (เช่น เมื่อเจ้าของข้อมูลขอให้ลบใบหน้าของเขา)

### ดาวน์โหลดไฟล์โมเดลด้วยตัวเอง (เฉพาะกรณีไฟล์หายหรืออยากอัปเดต)

ในโปรเจ็คมีไฟล์ครบอยู่แล้ว ข้ามขั้นนี้ได้ ถ้าต้องดาวน์โหลดใหม่ ใช้วิธีใดวิธีหนึ่ง:

**วิธี ก — สคริปต์ (ง่ายสุด)**
```bat
py scripts\download_face_api.py
```

**วิธี ข — โหลดเองทีละไฟล์**
1. เปิด https://github.com/vladmandic/face-api/blob/master/dist/face-api.js → กดปุ่ม Download raw file
   → บันทึกเป็น `static\vendor\face-api\face-api.js`
2. เปิด https://github.com/vladmandic/face-api/tree/master/model แล้วดาวน์โหลด 6 ไฟล์นี้
   ไปไว้ที่ `static\vendor\face-api\models\`
   - `tiny_face_detector_model.bin` และ `tiny_face_detector_model-weights_manifest.json`
   - `face_landmark_68_model.bin` และ `face_landmark_68_model-weights_manifest.json`
   - `face_recognition_model.bin` และ `face_recognition_model-weights_manifest.json`

ไฟล์ `.bin` และ `.json` ของแต่ละโมเดลต้องอยู่คู่กัน ชื่อต้องตรงตามนี้ทุกตัวอักษร

## 3. ตั้งค่า Google Sheet (ฟรี ไม่ต้องผูกบัตร)

ข้ามส่วนนี้ได้ถ้ายังไม่พร้อม — ระบบจะทำงานปกติ และแถวที่ยังไม่ได้ส่งจะรออยู่ในฐานข้อมูล
พอตั้งค่าเสร็จแล้วสั่ง `py manage.py sync_sheet` จะส่งย้อนหลังให้ทั้งหมด

การใช้ Google Sheets API ฟรี ไม่ต้องเปิด billing — ถ้า Google Cloud ขึ้นแบนเนอร์ชวนสมัครทดลองใช้/ผูกบัตร **ไม่ต้องกด**

1. **สร้างโปรเจ็ค Google Cloud**: เข้า https://console.cloud.google.com ด้วยบัญชี Google → ตัวเลือกโปรเจ็คด้านบน → **New Project** → ตั้งชื่อ เช่น `face-login-sheet` → Create
2. **เปิด Sheets API**: เมนู *APIs & Services* → *Library* → ค้นหา **Google Sheets API** → **Enable**
3. **สร้าง Service Account**: *IAM & Admin* → *Service Accounts* → **Create service account** → ตั้งชื่อ → Create → ข้ามขั้นให้สิทธิ์ (Continue/Done ได้เลย ไม่ต้องเลือก role)
4. **สร้างไฟล์ key**: คลิกที่ service account ที่เพิ่งสร้าง → แท็บ *Keys* → *Add key* → *Create new key* → เลือก **JSON** → Create
   ไฟล์ `.json` จะถูกดาวน์โหลดลงเครื่อง ให้ย้ายไปเก็บ **นอกโฟลเดอร์โปรเจ็ค** เช่น `C:\Users\ชื่อคุณ\secrets\face-login-sa.json`
   (ไฟล์นี้คือกุญแจ ใครได้ไปเขียนชีตของคุณได้ — ห้ามส่งต่อ ห้ามอัปโหลด GitHub)
5. **เปิดไฟล์ JSON** แล้วคัดลอกค่า `client_email` (หน้าตาเหมือน `xxx@yyy.iam.gserviceaccount.com`)
6. **สร้าง Google Sheet** ใหม่ (https://sheets.new) → ปุ่ม **Share** → วางอีเมลจากข้อ 5 → ให้สิทธิ์ **Editor** → Send
   **อย่าเปิดแชร์แบบ "ทุกคนที่มีลิงก์"** — ชีตนี้มีข้อมูลส่วนบุคคล ให้เฉพาะเจ้าของและ Service Account เท่านั้น
7. **คัดลอก Sheet ID** จาก URL ของชีต: `https://docs.google.com/spreadsheets/d/`**`ตรงนี้คือ_ID`**`/edit`
8. คัดลอก `.env.example` เป็น `.env` (ในโฟลเดอร์โปรเจ็ค) แล้วแก้สองบรรทัด:
   ```
   GOOGLE_SHEET_ID=ตรงนี้คือ_ID
   GOOGLE_SERVICE_ACCOUNT_FILE=C:/Users/ชื่อคุณ/secrets/face-login-sa.json
   ```
   (ใช้เครื่องหมาย `/` แม้เป็น Windows)
9. หยุดเซิร์ฟเวอร์ (Ctrl+C) แล้วรัน `py manage.py runserver` ใหม่ ล็อกอินหนึ่งครั้ง จะเห็นหัวตารางและแถวใหม่ในชีต

ถ้าใช้บัญชี Google ของโรงเรียน (Workspace) แล้วสร้าง key ไม่ได้ เพราะผู้ดูแลปิดไว้ ให้ใช้บัญชี Gmail ส่วนตัวแทน

**ระบบทำงานกับชีตอย่างไร**
- ล็อกอินสำเร็จ → บันทึก `LoginLog` ลงฐานข้อมูลก่อน (สถานะ "รอส่ง") → thread แยกส่งขึ้นชีต หน้าเว็บไม่ต้องรอ
- ส่งไม่สำเร็จ (เน็ตหลุด โควตาเต็ม) → ล็อกอินยังสำเร็จตามปกติ สถานะเป็น "ส่งไม่สำเร็จ (จะลองใหม่)"
- ลองใหม่อัตโนมัติเมื่อมีคนล็อกอินสำเร็จครั้งถัดไป หรือสั่งเอง: `py manage.py sync_sheet`
- ส่งแบบ RAW (เก็บเป็นข้อความตรง ๆ) กันคนตั้งชื่อเป็นสูตร เช่น `=HYPERLINK(...)`

## 5. ระบบทำงานอย่างไร (สรุปให้อธิบายได้)

**สมัครสมาชิก**
1. เบราว์เซอร์โหลดโมเดล 3 ตัวจาก `static/` เปิดกล้อง ตรวจใบหน้าสด ๆ และวาดกรอบ
2. กด "ถ่ายรูปหน้า" → ตรวจอีกรอบบนภาพนิ่ง ต้องเจอ **ใบหน้าเดียว** และไม่เล็กเกินไป → สกัด **descriptor** (ตัวเลข 128 ค่า)
3. ส่ง JSON (ข้อมูลฟอร์ม + descriptor + รูป) มาที่ Django พร้อม CSRF token
4. Django ตรวจข้อมูลอีกครั้ง (ไม่เชื่อเบราว์เซอร์), แฮช PIN ด้วย `make_password`, ย่อรูปและแปลงเป็น JPEG ใหม่, สร้างรหัสสมาชิกสุ่มที่ไม่ซ้ำ, เก็บหลักฐานการยินยอม PDPA พร้อมเวลา

**ล็อกอิน (ต้องผ่านทั้ง 3 อย่าง)**
1. ผู้ใช้กรอกชื่อ + PIN แล้วกดปุ่ม เบราว์เซอร์สกัด descriptor จากวิดีโอ ณ ตอนนั้น (ถ้าไม่เจอหน้าเดียวจะเตือนและ **ไม่ส่งอะไรเลย**)
2. Django เช็กว่าชื่อนี้ถูกล็อกอยู่ไหม → หาสมาชิกที่ชื่อตรง → เช็ก PIN ด้วย `check_password` → เทียบระยะ Euclidean กับ descriptor **ของเจ้าของชื่อนั้นเท่านั้น (1:1)** ผ่านเมื่อ `ระยะ < FACE_MATCH_THRESHOLD`
3. ไม่ผ่านข้อไหนก็ตอบข้อความเดียวกันว่า **"ข้อมูลไม่ถูกต้อง"**
4. ผ่านทั้งหมด → สร้าง session ใหม่ → บันทึก LoginLog → ส่งขึ้นชีตใน thread แยก

**ถ้ามีคนชื่อเดียวกันหลายคน**: ระบบตรวจ PIN ของทุกคนที่ชื่อตรง แล้วเทียบใบหน้ากับ "เฉพาะคนที่ PIN ถูก" ดังนั้นสองคนที่ชื่อเหมือนกันยังใช้งานได้ตราบใดที่ PIN หรือใบหน้าต่างกัน

**ความเป็นส่วนตัวของรูป**: โฟลเดอร์ `media/` ไม่ได้เปิดเป็น URL สาธารณะ รูปส่งผ่านหน้า `/me/photo/` ซึ่งให้ดูได้เฉพาะรูปของ "ตัวเองที่ล็อกอินอยู่" และชื่อไฟล์เป็นเลขสุ่ม

## 6. ทำไมเลือก threshold = 0.5 และทำไมเก็บ descriptor

### descriptor คืออะไร และทำไมไม่เทียบรูปตรง ๆ
- descriptor คือเลข 128 ตัวที่โมเดลสกัดจากใบหน้า ใบหน้าของคนเดียวกันจะได้เลขชุดที่ "ใกล้กัน" และคนละคนจะ "ไกลกัน" เราจึงวัดความเหมือนได้ด้วยการวัดระยะ
- การเทียบรูปตรง ๆ (พิกเซลต่อพิกเซล) ใช้ไม่ได้จริง เพราะรูปคนเดียวกันที่ถ่ายคนละแสง คนละมุม คนละสีหน้า จะต่างกันมากในระดับพิกเซล แต่โมเดลเรียนรู้มาให้ไม่สนใจสิ่งเหล่านั้น
- ตัวเลข 128 ค่าเล็กและเทียบเร็ว (คำนวณระยะด้วย `math.dist` บรรทัดเดียว) เซิร์ฟเวอร์ไม่ต้องมีไลบรารีวิเคราะห์ภาพหนัก ๆ ซึ่งตรงกับเงื่อนไขที่ห้ามใช้ dlib/OpenCV
- เรายังเก็บรูปไว้ด้วย แต่ **ใช้แสดงผลอย่างเดียว ไม่ใช้เทียบ**
- ข้อควรรู้: descriptor ไม่ใช่รูปภาพ แต่ยังนับเป็นข้อมูลชีวมิติ ต้องดูแลเข้มงวดเท่ากับรูปหน้า

### threshold 0.5
- ระยะ Euclidean ยิ่งน้อยยิ่งเหมือน ระบบจะยอมรับเมื่อ **ระยะ < threshold**
- ค่าเริ่มต้นของ face-api.js (`FaceMatcher`) คือ **0.6** เราเลือก **0.5** ให้เข้มงวดขึ้นเล็กน้อย เพราะเป้าหมายหลักของระบบคือกันไม่ให้คนอื่นสวมรอย
- ค่าต่ำ = กันคนอื่นได้ดีขึ้น แต่เจ้าของอาจโดนปฏิเสธบ่อยขึ้นเมื่อแสงไม่ดี ค่าสูง = สะดวกขึ้น แต่คนหน้าคล้ายกันอาจผ่านได้
- ระบบนี้เทียบแบบ 1:1 (ยืนยันว่าเป็นคนที่ชื่อนี้จริงไหม) และยังต้องผ่านชื่อ + PIN ด้วย จึงไม่ได้พึ่งใบหน้าอย่างเดียว

**ผลทดลองเบื้องต้นตอนสร้างโปรเจ็ค** (รันไปป์ไลน์ face-api จริงด้วยไฟล์โมเดลชุดเดียวกับในโปรเจ็ค และตั้งค่าตัวตรวจจับเหมือนในเว็บ กับรูปตัวอย่าง 6 รูปที่มากับไลบรารี):
- รูปเดียวกันแต่ปรับความสว่าง → ระยะประมาณ 0.10-0.12 (กรณีง่ายมาก ไม่ใช่การสแกนซ้ำจริง)
- ใบหน้า 17 ใบหน้าจากรูปเหล่านั้น จับคู่กัน 136 คู่ → ระยะต่ำสุด 0.42, กลาง ๆ 0.75, สูงสุด 0.91 โดยมี **1 คู่ที่ต่ำกว่า 0.5** และ **10 คู่ที่ต่ำกว่า 0.6**
- นี่เป็นตัวอย่างเล็ก ๆ จากรูปสต็อก ไม่ใช่กล้องเว็บแคม และบางคู่อาจเป็นคนหน้าคล้ายกัน จึง **ใช้แทนการประเมินความแม่นยำจริงไม่ได้** แต่พอเห็นภาพว่าทำไมค่า 0.5 ถึงกันคนอื่นได้เข้มกว่า 0.6

**สำคัญ: 0.5 เป็นจุดเริ่มต้นที่สมเหตุสมผล ไม่ใช่ค่าที่พิสูจน์แล้วว่าเหมาะกับกล้องและแสงของคุณ** แนะนำให้วัดเองแล้วเล่าให้กรรมการฟัง:
1. สมัครสมาชิกหนึ่งคน แล้วล็อกอินด้วยหน้าตัวเอง 10 ครั้ง ในแสง/มุมที่ต่างกัน จดค่า `distance` จาก terminal
2. ให้เพื่อน 3-5 คนลองใช้ชื่อ + PIN ของคุณ แต่ใช้หน้าตัวเอง (PIN ต้องถูกจึงจะมีการคำนวณระยะ) จดค่า `distance`
3. ถ้าค่าของคุณอยู่ต่ำกว่าค่าของเพื่อนอย่างชัดเจน ให้ตั้ง threshold ไว้ตรงช่องว่างระหว่างสองกลุ่ม แล้วเปลี่ยนใน `.env`: `FACE_MATCH_THRESHOLD=0.45`
4. ถ้าตัวเองโดนปฏิเสธบ่อย ลองเพิ่มแสงหน้าก่อนจะขยับ threshold ขึ้น

## 7. ข้อจำกัดของระบบ (ควรบอกกรรมการตรง ๆ)

1. **ตรวจใบหน้าที่ฝั่งเบราว์เซอร์ จึงไม่กันการปลอมแปลงเต็มรูปแบบ** — เซิร์ฟเวอร์รับ descriptor ที่เบราว์เซอร์ส่งมาโดยเชื่อว่ามาจากกล้องจริง คนที่รู้เทคนิคสามารถส่ง descriptor เองผ่านเครื่องมือนักพัฒนาโดยไม่ผ่านกล้องได้ แต่เขายังต้องรู้ชื่อ + PIN และต้องมี descriptor ของเป้าหมายด้วย
2. **ไม่มีการตรวจว่าเป็นคนจริง (liveness)** — เอารูปถ่ายหรือวิดีโอมาจ่อกล้องอาจผ่านได้ (เป็นฟีเจอร์เสริมที่วางแผนไว้)
3. **PIN 4-6 หลักมีความเป็นไปได้น้อย** (10,000 ถึง 1,000,000 แบบ) การแฮชช่วยไม่ได้มากถ้าฐานข้อมูลหลุด ระบบจึงพึ่งการล็อกชั่วคราวและใบหน้าเป็นชั้นป้องกันหลัก
4. **ล็อกชั่วคราวนับตามชื่อ** — เป็นข้อแลกเปลี่ยน: คนอื่นพิมพ์ชื่อคุณผิด ๆ 5 ครั้งจะทำให้คุณถูกล็อก 5 นาทีได้ (แต่เดา PIN ไม่ได้)
5. **ความแม่นยำขึ้นกับแสง กล้อง และมุมหน้า** ตัวตรวจจับที่ใช้ (TinyFaceDetector) เล็กและเร็วแต่แม่นน้อยกว่าตัวใหญ่ และสมัครจากรูปเดียว ถ้ารูปตอนสมัครไม่ดี ล็อกอินจะไม่เสถียร (สมัครใหม่ในที่สว่างจะช่วยได้มาก) โมเดลจดจำใบหน้าโดยทั่วไปอาจแม่นไม่เท่ากันในแต่ละกลุ่มคน จึงควรทดสอบกับหลายคนก่อนสรุปผล
6. **ออกแบบสำหรับรันบนเครื่องตัวเอง** ไม่ใช่สำหรับขึ้นอินเทอร์เน็ตจริง (ใช้ SQLite, dev server, HTTP, DEBUG เปิด, รูปและ descriptor ยังไม่เข้ารหัสในดิสก์) ถ้าจะเปิดใช้งานจริงต้องใช้ HTTPS, ปิด DEBUG, ตั้ง `DJANGO_SECRET_KEY` และเปลี่ยนฐานข้อมูล
7. **Google Sheet เก็บข้อมูลส่วนบุคคลไว้นอกเครื่อง** ต้องแชร์เฉพาะเจ้าของ และดูแลไฟล์ key ให้ดี
8. **สิ่งที่ยังไม่ได้ทดสอบจริงตอนสร้างโปรเจ็ค** (ให้ทดสอบเองตามตาราง 4.2):
   - **Google Sheet จริง** — ส่วนชีตทดสอบด้วยการจำลอง Google และด้วยการตั้งค่าที่เชื่อมต่อไม่ได้ (ล็อกอินยังสำเร็จและบันทึกสถานะ "ส่งไม่สำเร็จ" ถูกต้อง)
   - **กล้องเว็บแคมจริงในเบราว์เซอร์** — ตรรกะของหน้าเว็บทดสอบด้วยตัวจำลองกล้องและ face-api ส่วนตัวไปป์ไลน์ face-api ทดสอบด้วยรูปตัวอย่างใน Node
   - **หน้าตาของเว็บ (UI)** — ยังไม่ได้เปิดดูในเบราว์เซอร์จริง ถ้าเห็นอะไรผิดเพี้ยนให้แจ้งมาปรับได้

## 8. PDPA / ความยินยอม

หน้าสมัครมีช่องติ๊กยินยอมและบอกว่าเก็บอะไรบ้าง (รวมถึงการส่งชื่อ-รหัสสมาชิก-เวลาขึ้น Google Sheet) ระบบบันทึกเวลาที่ยินยอมไว้ในฐานข้อมูล และผู้ดูแลลบสมาชิกได้จาก `/admin/`
ข้อความยินยอมเป็นแบบร่างสำหรับโปรเจ็คโรงเรียน ไม่ใช่คำแนะนำทางกฎหมาย — ควรทดสอบกับตัวเองและคนที่ยินยอมจริง ถ้าผู้ทดสอบเป็นผู้เยาว์ควรให้ผู้ปกครองรับทราบ
และอย่าเผยแพร่รูป/ข้อมูลของผู้ทดสอบในพอร์ต (ใช้ภาพหน้าจอที่เบลอหน้า หรือใช้ข้อมูลของตัวเอง)
